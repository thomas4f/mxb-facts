# Reaching the project privately

Most things belong in a public issue: a [comment on an answer](../../issues/new?template=correction.yml) or a [request](../../issues/new?template=analyse-tool.yml).

Use a private report instead when the matter shouldn't be public:

- a security problem in this repository or its site;
- a card that shows something it shouldn't (a secret, personal data, details of a security problem that isn't fixed);
- you are a tool's author and want to say when a fix for a held-back item ships.

Open the repository's **Security** tab and choose **Report a vulnerability**. Only the maintainer sees it.

A security problem in a tool itself goes to that tool's author first, not here (`CLAUDE.md`, rule 9).
